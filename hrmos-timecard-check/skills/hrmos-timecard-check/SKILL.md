# HRMOS勤怠の打刻漏れ確認・補正

日次勤怠から補正が要る日を拾い、PC の操作記録から出勤・退勤時刻の候補を出して、
ユーザーの承認を得てから日次勤怠の編集画面で「登録する」を押す。

## 前提

- Claude in Chrome が接続されていること。HRMOS は Claude のタブグループ内のタブで開く
- **ログイン画面が出たら、ユーザーにそのタブでログインしてもらう。** ID・パスワードが自動入力されて
  いても、Claude からログインボタンは押さない
- **押すのは「登録する」だけ。「申請する」は押さない。** 申請は月末にユーザーが一括で行う
- 登録は、候補の一覧にユーザーの明示的な承認をもらってから行う
- PC の操作記録は、このスキルを実行している端末のものしか取れない。ユーザーが普段使う PC で実行する

## 対象日の決まり（ユーザーと合意済み）

当日より前の日だけを対象にする（当日はまだ退勤していないため触らない）。

- **打刻漏れ**：勤務区分が「出勤」で、出勤または退勤の時刻が空の日
- **総労働時間 7:30 未満**：勤務区分が「出勤」で、総労働時間が 7:30 未満の日。打刻の誤りが疑われるので、
  打刻漏れと同じ方法で出勤・退勤の候補を出し、どちらが誤りかを示す。
  「出勤（月例）」「出勤（午前休）」「出勤（午後休）」は対象外
- **第一土曜（月例）**：その月の第一土曜で、勤務区分が「出勤」の日。月例（月に一度集まり午前だけ会議を
  行う日）にあたるため、勤務区分を「出勤（月例）」にし、退勤は **12:00 に固定**する
  - 12:00 を過ぎて PC を操作していても 12:00 に帰ったものとする
  - 13:00 以降に PC の操作がある場合だけ、休日出勤の可能性ありとしてユーザーに報告する（基本は無い）
  - 出勤の打刻が漏れていれば、その日の PC の起動・復帰時刻を出勤の候補にする

## 時刻の候補の決め方

- **その日 PC を一度も起動・復帰していない** → 有給で休んだ可能性が高い。時刻は出さずにそう報告する
- **出勤の候補**：その日最初の起動（`Kernel-General` Id 12）またはスリープからの復帰
  （`Power-Troubleshooter` Id 1）の時刻
- **退勤の候補**：**人が最後に操作した時刻**を採る。優先順は次のとおり
  1. その日最後の画面ロック（Winlogon の通知イベント `(4)`）。これより後に解除 `(5)` が無いもの
  2. 手動のスリープ・シャットダウン（`Kernel-Power` Id 42 / 1074 等で、理由が Idle Timeout・
     Fixed Timeout 以外のもの）
  3. Claude への最後の指示時刻。指示だけしてスリープせずに帰ることがあり、その場合 PC は
     1〜2 時間後に自動でスリープする。自動スリープの時刻は退勤にしない
- 候補には必ず根拠のログ（時刻・種類）と、Claude への最後の指示時刻を添える

## 手順

1. **日次勤怠を開く。** `https://p.ieyasu.co/works` を開き、`get_page_text` で表を読む。
   ログイン画面になったらユーザーにログインしてもらう。別の月は画面上部の「YYYY年MM月度」で切り替える
2. **対象日を拾う**（上の「対象日の決まり」）
3. **PC の操作記録を取る**（後述のコマンド）。対象日ごとに、起動・復帰・ロック・解除・スリープを時系列に並べる
4. **候補を表にして見せる。** `日付 / 勤務区分 / 出勤（現在→候補） / 退勤（現在→候補） / 根拠` の表にし、
   有給の可能性・休日出勤の可能性がある日は別に書く
5. **承認をもらう。** ユーザーが時刻を訂正したらそれに従う
6. **登録する。** 一覧の日付の下にある鉛筆アイコンを押して編集画面（`/works/<id>/edit`）を開き、
   勤務区分・出勤・退勤を入れて、送信前に入力内容を見せてから **「登録する」** を押す
7. **確かめる。** 一覧に戻るので、対象日の出勤・退勤・総労働時間が反映されたことを読み直して報告する

## PC の操作記録を取るコマンド

Bash（Git Bash）から PowerShell を呼ぶ。`$_` が bash に展開されないよう、`-Command` は
シングルクォートで囲む。出力が文字化けしたら `| iconv -f cp932 -t utf-8` を付ける。

起動・復帰・スリープ・待機（`<開始>` `<終了>` は `2026-09-28 00:00` の形）:

```bash
powershell -NoProfile -Command 'Get-WinEvent -FilterHashtable @{LogName="System"; StartTime="<開始>"; EndTime="<終了>"; ProviderName="Microsoft-Windows-Kernel-Power","Microsoft-Windows-Power-Troubleshooter","Microsoft-Windows-Kernel-General","User32"} -ErrorAction SilentlyContinue | Sort-Object TimeCreated | ForEach-Object { $_.TimeCreated.ToString("MM/dd HH:mm:ss") + " " + $_.ProviderName + " Id=" + $_.Id + " " + (($_.Message -split "`n")[0..3] -join " / ") }' | iconv -f cp932 -t utf-8
```

画面のロック `(4)`・解除 `(5)`:

```bash
powershell -NoProfile -Command 'Get-WinEvent -FilterHashtable @{LogName="Microsoft-Windows-Winlogon/Operational"; StartTime="<開始>"; EndTime="<終了>"; Id=811} -ErrorAction SilentlyContinue | Where-Object { $_.Message -match "Sens" } | Sort-Object TimeCreated | ForEach-Object { $_.TimeCreated.ToString("MM/dd HH:mm:ss") + " " + (($_.Message -split "`n")[0]) }' | iconv -f cp932 -t utf-8
```

Claude への指示時刻（UTC で記録されているので +9 時間して JST にする。JST のある日は前日 15:00Z〜当日 15:00Z）:

```bash
grep -h '"type":"user"' ~/.claude/projects/*/*.jsonl | grep -v '"tool_use_id"' | grep -o '"timestamp":"<YYYY-MM-DD>T[0-9:]*' | sort | tail -5
```

## 落とし穴

- **システムログの `Kernel-Power` Id 566「Reason SessionUnlock」は、人がロックを解除した記録ではない。**
  システム内部のセッションの切り替わりに付く名前で、PC が待機状態のまま出ることがある
  （2026-09-28 21:04 に、帰宅後の無人の PC で出ていた）。人のロック・解除は Winlogon の通知
  イベント `(4)` / `(5)` で判断する。9/28 は `(4)` と `(5)` が交互に出ていて、昼休み
  （12:00 ロック → 13:14 解除）とも合っていた
- 待機状態は `Kernel-Power` Id 506（入る）/ 507（抜ける）で、理由が付く。「Idle Timeout」は操作がなく自動で
  入ったもの。Id 42 の「Hibernate from Sleep - Fixed Timeout」は、待機が続いたため自動で休止に移ったもので、
  人の操作ではない
- 朝の Winlogon の解除 `(5)` は、復帰・打刻より遅れて出ることがある（9/29 は復帰 08:56、`(5)` は 09:12）。
  出勤の候補には起動・復帰の時刻を使う
- **一覧の「申請」ボタンは、出勤・退勤が揃っていない日に押すとブラウザのダイアログ
  「「出勤」または「退勤」時刻が未登録です。」が出て、閉じるまでタブが操作できなくなる**
  （スクリーンショットも取れない）。Claude からは閉じられないので、ユーザーに OK を押してもらう。
  補正は一覧の「申請」ではなく、日付の下の鉛筆アイコンから行う
- 編集画面の時刻欄は、クリックして `HH:MM` を入力すれば入る。日をまたぐ退勤は「翌日」にチェックを入れる
- 休憩1 は 12:00〜13:00 が最初から入っている。触らない
