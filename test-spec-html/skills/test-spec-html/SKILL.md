# テスト仕様書 HTML 生成スキル

機能仕様書（Markdown）を入力に、**テスト実施結果を保存できる単一ファイルの HTML テスト仕様書**を生成する。
生成物はサーバー不要でブラウザに直接開ける自己完結 HTML（外部依存なし）。

## いつ使うか

- 「〇〇（仕様書）からテスト仕様書を HTML で作って」と依頼されたとき
- 機能テストと画面操作パターンを網羅したテスト表が欲しいとき
- テスト実施結果（合否・実施日・実施者・備考）を記録・保存できる形式が求められたとき

## 生成物の必須要件

1. **単一 HTML ファイル**（CSS/JS をインラインに内包、外部CDN・外部フォント・外部画像を使わない）。
2. テスト項目を**カテゴリ別**に整理し、以下を網羅する:
   - **機能テスト**（各機能の正常系・異常系・境界値・バリデーション）
   - **画面操作パターン**（画面遷移・操作の組み合わせ・タブ/モード切替・キー操作など）
3. 各テスト項目に **結果(未実施/OK/NG/対象外)・実施日・実施者・備考** の入力欄を持ち、
   入力内容を **ブラウザ localStorage に自動保存**する（再度開いても保持）。
4. 結果を「未実施」から他の値へ変更した瞬間に、**実施日へ当日日付／実施者へ上部テキストボックスの値**を
   自動セットする（**既に値が入っている欄は上書きしない**）。
5. 画面上部の「既定テスト実施者」テキストボックスの値も保存・復元する。
6. **進捗サマリ**（総数/OK/NG/対象外/未実施 と進捗バー）、**絞り込み**（すべて/未実施/OK/NG）、
   **JSON エクスポート/インポート**（別端末への引き継ぎ用）、**印刷対応**を備える。
7. **ヘッダ等の低コントラストを避ける**（暗背景に半透明の薄い文字を置かない。入力欄は白背景＋濃色文字）。

## 手順

1. **入力の仕様書を精読する。** 機能一覧・業務フロー・画面操作キー・入力項目・バリデーション・
   業務ルール・スコープ境界・関連機能（画面遷移）をすべて洗い出す。
2. **テストケースを設計する。** 仕様の各節を漏れなくカテゴリ化する。目安の観点:
   - 画面表示・初期化（起動経路・初期データ・表示項目の網羅・状態クリア）
   - 各機能ごとの操作（正常系）
   - 境界・異常系（未選択・先頭/末尾・上限/下限・0件・桁あふれ 等）
   - バリデーション（チェック順・エラー表示方式・エラー回復・確認ダイアログの「いいえ」）
   - 保存/更新（更新対象・トランザクション・ロールバック・戻り先反映）
   - 終了/キャンセル（未保存確認・破棄・継続）
   - 重要業務ルールの検証（仕様書に具体例があれば、その具体例をそのままケース化する）
   - 排他制御・親子画面連携
   - **複合操作・画面遷移パターン**（実運用を想定した操作の組み合わせを1カテゴリ設ける）
3. **テンプレートを複製して埋める。** このスキルの `assets/template.html` をベースにし、
   以下の差し替えポイントだけを書き換える（CSS/JS ロジックは変更不要）:
   - `<title>` と `header.doc` 内の画面名・メタ情報（プログラム名・配置先・元仕様書パス・呼び出し元 等）
   - `const CASES = [ ... ]`（テストケース定義。構造は下記）
   - `const STORE_KEY`（`test-spec:<画面英名>:v1` の形式。画面ごとに一意にする）
   - `footer` の元仕様パス、`exportJson()` の `a.download` ファイル名
4. **出力先。** 原則、入力仕様書と同じフォルダに `<画面名>_テスト仕様書.html` として保存する
   （ユーザー指定があればそれに従う）。
5. **表示確認。** 生成後に、結果切替→実施日/実施者の自動セット、リロード後の保持、進捗集計、
   絞り込み、コントラストが破綻していないかを確認する。

## CASES の構造

```js
const CASES = [
  { cat:"INIT", catName:"画面表示・初期化", intro:"このカテゴリの説明（任意）",
    items:[
      { id:"INIT-01", title:"確認項目名",
        pre:"前提条件",
        steps:["操作手順1","操作手順2"],
        exp:["期待結果1","期待結果2"] },
      // ...
    ]},
  // ... カテゴリを続ける
];
```

- `id` はカテゴリ接頭辞＋連番（例 `VAL-03`）。**localStorage の保存キーになるため、一度公開したら変えない。**
- `steps` / `exp` は配列（複数手順・複数期待結果を箇条書き表示）。
- `cat` はセクション見出しの識別子、`catName` は表示名。

## 注意

- localStorage は**ファイルの置き場所（オリジン）と `STORE_KEY` に紐づく**。ファイル名を変えても
  同一フォルダなら保持されるが、別フォルダへ移動すると別データ扱いになる。引き継ぎは JSON 入出力を案内する。
- テストケースは仕様書の記述に忠実に。仕様に無い挙動を勝手に期待結果へ書かない。
  仕様が曖昧な箇所は期待結果に「（仕様どおりの挙動になること）」等の含みを持たせるか、ユーザーに確認する。
- このスキルは自作スキルであり、`~/.claude/rules/custom-skill-workflow.md` の管理フロー
  （original-claude-plugins リポジトリでの git 管理）に従って配置・更新されている。
